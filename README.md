# openapi-shape

[![npm version][npm-version-src]][npm-version-href]

[![Node.js][node-src]][node-href]
[![License][license-src]][license-href]

TypeScript for any OpenAPI 3.0, 3.1, or 3.2 API, in one generated module: every operation keyed by `"METHOD /path"`, every schema as a named type, and a small runtime `contract` that lets the optional client call the API exactly as described. Use the types with your own client, or with this one.

- **Works with the real API.** Generation follows the OpenAPI and JSON Schema specifications, version by version. Where a document's letter and the API it describes part ways (a file upload typed `format: binary` in 3.1, `nullable` beside `allOf`), the output follows the API and a warning says where.
- **Small.** One generated `.ts` file; the client is one dependency-free module.
- **CI-ready.** `--check` fails when the committed file is out of date.

## Quick start

```sh
pnpm add openapi-shape
pnpm exec openapi-shape ./openapi.yaml -o src/api.ts
```

The source may be a file path or an HTTP(S) URL, in JSON or YAML; `$ref`s to other files and URLs are followed. Call the API through the typed client:

```ts
import { createClient } from "openapi-shape/client"
import { contract } from "./api"

const api = createClient({ contract, security: { bearer: token } })

const pets = await api("GET /pets", { query: { limit: 10 } }) // Schemas.Pet[]
const pet = await api("POST /pets", { body: { name: "Rex" } }) // Schemas.Pet
```

Or use the types alone:

```ts
import type { Endpoints, Schemas } from "./api"

type Pet = Schemas.Pet
type ListPets = Endpoints["GET /pets"]["response"]["200"] // Schemas.Pet[]
```

If you only need types, `-o src/api.d.ts` writes them alone, for use with your own client; `pnpm add -D` is then enough. Content is typed as the bundled client decodes it (a file download is a `Blob`, for instance), so decode it the same way ([Media types](#media-types)).

## The generated file

```ts
// Petstore 1.0.0
//
// Generated by openapi-shape from an OpenAPI 3.2.0 document. Do not edit.

import type { Contract } from "openapi-shape/client"

export interface Endpoints {
  /**
   * List pets
   *
   * @operationId listPets
   */
  "GET /pets": {
    query: {
      /** @maximum 100 */
      limit?: number
    }
    response: {
      /** A page of pets */
      "200": Schemas.Pet[]
      /** Unexpected error */
      "default": Schemas.Error
    }
    responseHeaders: { "200": { "x-next"?: string } }
  }
  "POST /pets": {
    body: { "application/json": Schemas.NewPet }
    response: { "201": Schemas.Pet }
  }
  "GET /pets/{petId}": {
    params: { petId: number }
    response: { "200": Schemas.Pet; "404": Schemas.Error }
  }
  // …
}

export interface Webhooks {
  "POST pet.created": {
    headers: { "x-signature": string }
    body: { "application/json": Schemas.Pet }
    response: { "200": { received: number } }
  }
}

export namespace Schemas {
  export interface Pet {
    id: number
    name: string
    /** @format date-time */
    born?: string
  }
  // …
}

/** Credentials for `createClient({ security })`, by security scheme. */
export interface Security {
  bearer?: string
}

/** How requests go over the wire, for `createClient({ contract })` from openapi-shape/client. */
export const contract: Contract<Endpoints, Security> = {
  servers: ["https://api.example.com/v1"],
  security: { bearer: { type: "http", scheme: "bearer" } },
  requires: [{ bearer: [] }],
  endpoints: {
    "PATCH /pets/{petId}": { contentType: "application/merge-patch+json" },
    "POST /upload": { contentType: "multipart/form-data" },
  },
}
```

### Operations

`Endpoints` holds every operation under `paths`, `Webhooks` every webhook, and `Callbacks` every callback. All three share one entry shape. Each entry is keyed by `"METHOD target"`:

| Interface   | Key                                                       |
| ----------- | --------------------------------------------------------- |
| `Endpoints` | `"GET /pets/{petId}"`                                     |
| `Webhooks`  | `"POST pet.created"` (the webhook name)                   |
| `Callbacks` | `"POST /subscribe > onEvent > POST {$request.body#/url}"` |

Callback keys chain the parent operation, the callback name, and the callback's own method and URL expression; nested callbacks continue the chain. Methods are uppercase. OpenAPI 3.2's `query` field becomes `QUERY`, and `additionalOperations` keys are used exactly as declared, as the spec requires.

An entry has these members. A member is present only when the operation declares something for it, except `response`, which is always present:

| Member            | Type                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------- |
| `params`          | Path parameters, all required, typed by their schemas.                                  |
| `query`           | Query parameters, or (3.2) the type of the single `in: querystring` parameter.          |
| `headers`         | Header parameters.                                                                      |
| `cookies`         | Cookie parameters.                                                                      |
| `body`            | Request body as a map from media type to type; `body?:` when `required` is not `true`.  |
| `response`        | Map from status key (`"200"`, `"4XX"`, `"default"`) to the response type; `{}` if none. |
| `responseHeaders` | Map from status key to response headers, for statuses that declare headers.             |

A response type is the union of its media types' types, or `undefined` when the response has no content. Documentation (summary, description, `operationId`, deprecation, external docs) becomes JSDoc on entries, parameters, and responses.

### Webhooks and callbacks

The API sends webhook and callback requests, and your server answers them, so `Webhooks` and `Callbacks` are types only, for your handlers; the client and the contract leave them out. In their entries, `headers`, `query`, and `body` are what you receive, and `response` is what you return:

```ts
import type { SuccessOf } from "openapi-shape/client"
import type { Webhooks } from "./api"

type PetCreated = Webhooks["POST pet.created"]

export async function onPetCreated(request: Request): Promise<Response> {
  // Verify the signature before trusting the payload (see below).
  const pet: PetCreated["body"]["application/json"] = await request.json()
  return Response.json({ received: pet.id } satisfies SuccessOf<PetCreated>)
}
```

The types describe what the API documents, not what reaches your server: a webhook URL takes requests from anyone. Check the sender first (the signature header the document declares is in `headers`), and validate the payload at runtime where a malformed one would do harm.

### Schemas

Every entry of `components.schemas` becomes a declaration in the `Schemas` namespace, in document order. A plain object becomes an `interface`; anything else becomes a `type` alias. Names are kept when they are valid identifiers; other characters become `_`, and reserved words get a `_` prefix (`user-id` → `user_id`, `class` → `_class`). If two names collide, the later one gets a number (`User_Profile2`) and a `renamed-schema` warning.

Some schemas outside `components.schemas` are named too. These are the ones defined in other documents' components, under `$defs`, as whole schema files, or with an `$id`. A component that only references such a schema lends it its name. Other referenced schemas are inlined where first used; one referenced again, or recursively, gets a name from its location.

JSDoc on declarations and properties carries the title, description, deprecation, and the constraints TypeScript cannot express: `@format`, `@default`, `@minimum`, `@maximum`, `@exclusiveMinimum`, `@exclusiveMaximum`, `@multipleOf`, `@minLength`, `@maxLength`, `@pattern`, `@minItems`, `@maxItems`, `@uniqueItems`, `@minProperties`, `@maxProperties`, `@contentMediaType`, `@contentEncoding`, `@readOnly`, `@writeOnly`, and `@see`.

#### Input variants

A required `readOnly` property is required in responses only, and a required `writeOnly` property in requests only. A schema with such properties gets a second declaration, `<Name>Input`, with the request-side requiredness, which what you send refers to; the main declaration has the response side:

```ts
export interface User {
  /** @readOnly */
  id: number
  /** @writeOnly */
  password?: string
}
export interface UserInput {
  /** @readOnly */
  id?: number
  /** @writeOnly */
  password: string
}
```

The variant is emitted only when something you send uses the schema, and it propagates to schemas that contain one. `readOnly` and `writeOnly` count when set on the property, on a schema it references, or in an `allOf` member, and a property one `allOf` member declares and another requires is one-sided too. Webhook and callback requests are sent by the API, so they use the main declaration, and their responses, which you send, use the variants.

This is OpenAPI 3.0's rule; 3.1+ calls `readOnly` and `writeOnly` annotations, but APIs written for 3.1 still mean them this way, so the rule applies there too, with a `lenient-read-only` warning where it does.

### Formats

Formats change the types, not the values. The client sends and returns JSON as JSON, so a `date-time` arrives as a string and an `int64` as a number (beyond 2^53, imprecisely). Map a format to `Date` or `bigint` only together with an adapter that converts such values both ways; otherwise, map it to a type JSON yields, such as a branded `string`.

### Security and the runtime contract

[The client](#client) needs two things beyond `Endpoints`, and the module ends with them:

- `Security`: the credential each security scheme takes, a string or, for HTTP Basic, `{ username, password }`. Mutual TLS is left to the transport.
- `contract`: how requests go over the wire, with no secrets in it. In OpenAPI's own terms:
  - `servers`: every server URL, its variables set to their defaults. A relative URL is resolved against the document's location when the document was fetched over HTTP(S), and kept relative otherwise; such a document without `servers` uses its own origin.
  - `security`: each security scheme's type and where its credential goes, under the names `Security` uses.
  - `requires`: the default Security Requirements, any one of which suffices.
  - `endpoints`: per operation, only what differs from OpenAPI's defaults:
    - `servers`, when the operation or its path declares its own, and `requires`, when the operation declares its own security.
    - Parameter encodings under `params`, `query`, `headers`, and `cookies`: `{ style, explode }` (with `allowReserved` when set), or `{ contentType }` for a parameter with `content`.
    - The 3.2 `querystring` media type, or for form content, its Encoding Objects under `query`.
    - `contentType`: the media type to send when the call names none and it is not JSON, because it is the only one declared.
    - `encoding`: the Encoding Objects of form and multipart bodies, by media type.

`contract` is typed by `Contract` from `openapi-shape/client` through `import type`, so the module imports nothing at run time. A `.d.ts`, `.d.mts`, or `.d.cts` output leaves out `Security` and `contract`: it is types only.

## CLI

```sh
openapi-shape <source> [-o <file>] [--check] [--formats <name=type,...>]
```

| Option                        | Description                                                                                                                                                                        |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<source>`                    | File path or URL of a JSON or YAML OpenAPI document.                                                                                                                               |
| `-o, --output <file>`         | Write to `<file>`, a `.ts`, `.mts`, or `.cts` file (directories are created); a `.d.ts`, `.d.mts`, or `.d.cts` file gets types only. Without `-o`, the full module goes to stdout. |
| `--check`                     | Exit with 1 if `<file>` is missing or differs; write nothing. Prints the first difference.                                                                                         |
| `--formats <name=type,...>`   | Map OpenAPI `format`s to TypeScript types, e.g. `date-time=Date,int64=bigint` (commas inside a type are kept); repeated, the mappings add up. Types only; see [Formats](#formats). |
| `-h, --help`, `-v, --version` | Help, version.                                                                                                                                                                     |

Diagnostics go to stderr, at most three per code followed by a count. The exit code is 0 on success and 1 when generation fails, `--check` finds the file stale, the file cannot be written, or the arguments are invalid (including unknown options and a repeated `-o`).

```json
{
  "scripts": {
    "api": "openapi-shape ./openapi.yaml -o src/api.ts",
    "api:check": "openapi-shape ./openapi.yaml -o src/api.ts --check"
  }
}
```

## Programmatic API

```ts
import { generate, GenerateError } from "openapi-shape"

try {
  const { code, diagnostics } = await generate("./openapi.yaml")
  for (const d of diagnostics) console.warn(`${d.code} at ${d.location}: ${d.message}`)
} catch (error) {
  if (error instanceof GenerateError) console.error(error.diagnostics)
  else throw error
}
```

`generate(input, options?)` takes a file path, a `URL`, or an already parsed document object, and resolves to `{ code, diagnostics }`. If the description cannot be turned into correct types, it rejects with a `GenerateError` whose `diagnostics` lists every error found.

| Option         | Description                                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `formats`      | Map `format` values to TypeScript types, emitted verbatim, for string and number schemas with that format; `binary` sets the type of raw binary content (default `Blob`). Types only; see below. |
| `base`         | For a parsed document: its location (path or URL), so relative `$ref`s can be resolved. Without it, references must stay inside the document.                                                    |
| `declarations` | Emit types only, for a `.d.ts` file: no `Security` or `contract`.                                                                                                                                |

## Client

`openapi-shape/client` turns the generated module into one typed function. Given the `contract`, it serializes each request the way the description declares (parameter styles, media types, credentials, servers) and hands it to an adapter. It does not validate responses.

```ts
import { createClient, HttpError } from "openapi-shape/client"
import { contract } from "./api"

const api = createClient({
  contract,
  security: { bearer: () => token }, // called per request, so it may refresh
})

try {
  const pet = await api("GET /pets/{petId}", { params: { petId: 1 } })
} catch (error) {
  if (error instanceof HttpError && error.status === 404) {
    // error.body is the decoded response body
  }
}
```

`createClient` infers everything from what it is given: endpoints and credentials from `contract`, adapter options from `adapter`.

| Client option | Description                                                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `contract`    | The generated `contract`.                                                                                                                               |
| `server`      | The server URL endpoint paths go under. Default: the endpoint's own server, else the document's first server. Formerly `baseUrl`, which is now refused. |
| `security`    | Credentials by security scheme, typed by the generated `Security` (see [Security](#security)).                                                          |
| `headers`     | Sent with every request; per-call `headers` override them.                                                                                              |
| `options`     | Default adapter options; plain objects are shallow-merged with each call's `options`.                                                                   |
| `adapter`     | The transport. Default: `fetchAdapter()`.                                                                                                               |

The second argument is required exactly when the operation requires something:

| Option        | Rule                                                                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `params`      | Required when the path has parameters.                                                                                                        |
| `query`       | Required when any query parameter is required.                                                                                                |
| `headers`     | Optional. Declared header parameters are type-checked; other headers are allowed.                                                             |
| `cookies`     | Optional. Sent as a `cookie` header (browsers drop it).                                                                                       |
| `body`        | Required when the request body is required. A `Blob`, `FormData`, `URLSearchParams`, buffer, or stream is always accepted and passed through. |
| `contentType` | Which declared media type `body` is. May be omitted for the default (below).                                                                  |
| `options`     | Passed to the adapter (for the fetch adapter: `RequestInit` fields such as `signal`).                                                         |

The default media type is the one that takes JSON (`application/json`, `*/*`, or `application/*`), else the only one declared; when several are declared and none takes JSON, the call names one. `contentType` is always one of the declared media types; for a wildcard such as `image/*`, pass a `Blob`, whose own type is sent. What `body` may be follows the media type ([Media types](#media-types)): the schema's type for those the client encodes, a string for `text/*`, and otherwise a `Blob`, buffer, stream, or string. `fetch` cannot send a body with `GET` or `HEAD`; such a call rejects, so use an adapter that can.

The return type is the union of the `2xx`/`2XX` response types. If no 2xx response is declared, it is the `default` response, if any; otherwise `unknown`. `SuccessOf<Op>` and `ErrorOf<Op>` (`4xx`, `5xx`, and `default`) are exported for your own code; a single status is `Endpoints["GET /pets/{petId}"]["response"]["404"]`.

```ts
await api("POST /upload", { body: { file, name: "a.png" } }) // multipart, the only media type
await api("PATCH /pets/{petId}", { params: { petId: 1 }, body: { name: "Rex" } })
```

### Security

Each request uses the operation's security requirements, or, where it declares none, the document's. Of these, it applies the first whose schemes all have a credential in `security`, trying those that need credentials before those that need none (`{}`, or mutual TLS alone), so that credentials you give are sent wherever the operation accepts them. A credential may be a function, called per request, sync or async; when it returns nothing, the next requirement is tried. Where neither the operation nor the document declares security, every credential given is sent, and generation says so (`lenient-security`).

| Scheme                                      | Credential               | Sent as                                      |
| ------------------------------------------- | ------------------------ | -------------------------------------------- |
| `apiKey`                                    | string                   | The named header, query parameter, or cookie |
| `http`, `basic`                             | `{ username, password }` | `Authorization: Basic …`                     |
| `http`, `bearer`; `oauth2`; `openIdConnect` | token                    | `Authorization: Bearer <token>`              |
| `http`, another scheme                      | string                   | `Authorization: <Scheme> <credential>`       |
| `mutualTLS`                                 | —                        | Configure the transport (`adapter`).         |

### Serialization

Requests are encoded as the contract declares: every path, query, header, and cookie style (`label`, `matrix`, `pipeDelimited`, `deepObject` as `created[gte]=1`, …), `allowReserved`, JSON `content` parameters, the 3.2 `querystring`, and the Encoding Objects of form and multipart bodies. Bodies are encoded by media type: JSON, JSON sequences (an array, one item per line), `application/x-www-form-urlencoded` (or a string already encoded), `multipart/form-data` (Blobs as files, objects as `application/json` parts, other values as plain fields, arrays as repeated parts, values as given; a part whose Encoding Object declares one concrete `contentType` other than `text/plain` is labelled with it, text as UTF-8, without becoming a file, so the body is written out as a `Blob`: `FormData` labels a part only by making it a file. `text/plain` makes a part a plain field, as some servers, such as formidable, need for every field that is not a file), and `text/*`; streams, web or Node.js, pass through. `Date` values become ISO strings; `null` and `undefined` parameters are left out.

Values are percent-encoded; commas between list items stay as they are, and space and pipe delimiters are percent-encoded. A `Blob` is refused wherever the client writes text or JSON (a JSON or JSON-sequence body, a form field, an object part, a parameter, a header, a cookie), not sent as `{}`. `allowReserved` keeps reserved characters only where they cannot change the URL: in a path, all but `?`, `#`, `[`, and `]`; in a query or form field, also not `&`, `=`, and `+`; existing percent-encodings stay as they are. A path parameter value that would empty its segment or make it `.` or `..` is refused, since the request would reach another resource.

### Adapters

By default, requests go through `fetchAdapter()`. It decodes responses by the classes of [Media types](#media-types), so the result matches the type:

- JSON (`…/json`, `…+json`): parsed.
- `text/event-stream`: an array of `{ data, event?, id?, retry? }`; events without data are not dispatched. JSON sequences: an array of items.
- Other `text/*`: a string.
- An empty body without a content type, and `HEAD`, 204, 205, 304: `undefined`.
- Anything else: a `Blob`.

Streaming request bodies are sent in half duplex. A non-2xx status rejects with `HttpError` (`status`, `body`, `response`); a body that does not decode is kept as text.

To change how requests are made (timeouts, retries, logging, a test double), pass any `fetch`-compatible function to `fetchAdapter`; decoding stays as the types expect:

```ts
import { createClient, fetchAdapter } from "openapi-shape/client"
import { contract } from "./api"

const timed: typeof fetch = (input, init) =>
  fetch(input, { ...init, signal: init?.signal ?? AbortSignal.timeout(10_000) })

export const api = createClient({ contract, adapter: fetchAdapter(timed) })
```

An adapter for another transport is a function from the request (`method`, `url`, `headers`, `body`, `options`) to the decoded body of a success response, rejecting otherwise. It must decode as `fetchAdapter` does, since the types say so: JSON parsed, event streams and JSON sequences as arrays, other text as a string, anything else as a `Blob`. Its `options` type becomes the per-call `options`.

## OpenAPI support

### Versions and documents

- OpenAPI **3.0.x, 3.1.x, and 3.2.x**, each with its own rules. Every document in a description uses its own `openapi` version; schema-only documents use the entry document's. Swagger 2.0, other versions, and documents without `openapi` are rejected.
- JSON and YAML, from files, `file:` URLs, HTTP(S) URLs, or parsed objects.
- References resolve as URIs, against the document's location, `$self` (3.2), or the nearest `$id` (3.1+). Targets can be any JSON Pointer or `$anchor`, in any document. A document fetched over HTTP(S) may not reach local documents, except by the address one publishes as its `$self`, nor claim local files' URIs through `$id` or `$self`, and a parsed object without `base` may not reference anything outside itself. When documents claim the same URI, the one referenced first keeps it. YAML merge keys (`<<`) are read.
- Non-schema Reference Objects resolve anywhere a component may be referenced, including 3.2 media types. In 3.1+, their `summary` and `description` override the target's. A Path Item `$ref` is merged with its local fields; local fields win, with a `path-item-conflict` warning.

### Operations

- Path Item methods: `get`, `put`, `post`, `delete`, `options`, `head`, `patch`, `trace`, plus `query` and `additionalOperations` (3.2). The 3.2 fields and `in: querystring`, and `webhooks` in 3.0, are applied in earlier versions too, with a `lenient-keyword` warning.
- Parameters from the Path Item and the operation are merged. The operation's definition wins for the same name and location, and header names compare case-insensitively. Parameters are typed by `schema`, or by their single `content` entry.
- Header parameters named `Accept`, `Content-Type`, or `Authorization` are ignored, as the spec requires, as is a response header named `Content-Type`.
- Path parameters must match the path template. A template variable without a parameter is typed `string`; a parameter missing from the template is dropped. Both are reported.
- Request bodies on `GET`, `HEAD`, and `DELETE` are kept, in 3.0 too (`lenient-request-body`). Lowercase status ranges (`2xx`) are normalized to `2XX`; status keys that differ only in case are merged.

### Media types

Content is typed as the bundled client sends or returns it, by the same media type classes, so that types and the wire agree. A client of your own, or an adapter, decodes the same way to match. Webhooks and callbacks run the other way, and your handler reads their requests and writes their responses: both are typed as the Request body column says, so form and multipart content is typed by its schema (form fields arrive as text, whatever their schema's type).

| Media type                                                                                        | Request body                                                                        | Response                                                                                     |
| ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| JSON: `…/json`, `…+json`, and the wildcards `*/*` and `application/*`                             | Its schema (`unknown` without one)                                                  | The same                                                                                     |
| `text/event-stream`                                                                               | `Blob`                                                                              | `{ data: string; event?: string; id?: string; retry?: number }[]`, or the `itemSchema` items |
| JSON sequences: `application/jsonl`, `application/x-ndjson`, `application/json-seq`, `…+json-seq` | An array of `itemSchema` items, or of `schema` read as the item (`lenient-keyword`) | The same                                                                                     |
| Other `text/*`                                                                                    | `string`, or the schema's type when it says which strings                           | The same                                                                                     |
| `application/x-www-form-urlencoded`, `multipart/form-data`                                        | Its schema                                                                          | `Blob`                                                                                       |
| Anything else: binary, XML, YAML, vendor types                                                    | `Blob`                                                                              | `Blob`                                                                                       |

A string of raw bytes (`format: binary`, a binary `contentMediaType` without `contentEncoding`, or Swagger's `type: file`) is a `Blob` in a schema, as files are declared; under `text/*` the content is a `string`, and a wildcard (`*/*`) response whose schema is, or may be, raw bytes also admits a `string`, since the client decodes it by its actual type. In `multipart/form-data`, a part is a file (`Blob`, or `Blob[]` for an array property) when its schema is raw bytes, has no type keywords (its default content type is then `application/octet-stream`), or when its Encoding Object's `contentType` is a binary media type. Untyped parts are typed so over the schema's type, which keeps its name: `Schemas.Upload & { file?: Blob }`. A text part an Encoding Object makes a file is replaced when only the body's own schema declares it, which is then spelled out; one that a referenced schema declares, too, stays text, with an `ignored-keyword` warning (send a `FormData` to upload it).

### Schemas

| Schema                                      | TypeScript                                                                                                                                                        |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `true`, `{}`, annotations only              | `unknown`                                                                                                                                                         |
| `false`, `not: {}`, empty `enum`            | `never`                                                                                                                                                           |
| `type` (or 3.1+ `type` arrays)              | `string`, `number` (also for `integer`), `boolean`, `null`, arrays, objects, or their union                                                                       |
| `const`, `enum`                             | Literal types, including object and array literals; values outside `type` are dropped                                                                             |
| `format`                                    | Unchanged type plus `@format`; user `formats` replace it. `format: binary` is raw bytes, a `Blob` ([Media types](#media-types)); `format: byte` is base64 text    |
| `items`, `prefixItems`                      | `T[]`; tuples whose elements beyond `minItems` are optional, closed by `items: false`; labelled (`[_0?: T[]]`) where a recursive type would otherwise not compile |
| `properties`, `required`                    | Properties, required or optional. A required property that is not declared is typed from `patternProperties`, `additionalProperties`, or `unknown`                |
| `additionalProperties`, `patternProperties` | An index signature, widened to admit the declared properties                                                                                                      |
| `allOf`                                     | Intersection; plain object members are merged into one object                                                                                                     |
| `anyOf`, `oneOf`                            | Union                                                                                                                                                             |
| `if`/`then`/`else`                          | `(if & then) \| else`                                                                                                                                             |
| `$ref`                                      | The target, intersected with the other keywords                                                                                                                   |
| `$dynamicRef`                               | Resolved like `$ref` (with a `dynamic-ref` warning)                                                                                                               |
| `nullable: true`                            | The schema also admits `null`, wherever `nullable` appears                                                                                                        |

Validation-only keywords (`minimum`, `pattern`, `uniqueItems`, `contains`, `dependentRequired`, `unevaluatedProperties`, …) do not change the type. Several rows go beyond what OpenAPI 3.0 or 3.1 defines; see [Following the real API](#following-the-real-api).

### Discriminators

A Discriminator Object is a hint that must not change validation. So it only narrows types a schema leaves open:

- In a `oneOf`/`anyOf`, each referenced alternative is intersected with its discriminator values: the `mapping` values pointing to it, or else its component name. An example is `(Cat & { petType: "cat" }) | (Dog & { petType: "Dog" })`.
- A component that extends a discriminated schema through `allOf` gets the values of itself and of every component extending it in turn.
- An alternative that already declares string literals for the property keeps them. An explicit mapping that contradicts them is reported (`discriminator-mismatch`), as is an alternative that is not an object.
- Inline alternatives and the 3.2 `defaultMapping` target are not narrowed.

## Following the real API

The generated code exists to call real APIs, and real descriptions do not always say by the letter of their OpenAPI version what the API does. Where a document's intent is evident, the output follows it, and a `lenient-*` warning marks each place, so that nothing departs from the specification silently:

| Code                   | The letter of the specification                                                                                                                                                                                                                                                                                                                                                                                  | The output                                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `lenient-format`       | 3.1+: a string is text; raw bytes have no `type`. `type: file` is Swagger 2.0.                                                                                                                                                                                                                                                                                                                                   | Such a string is read as raw bytes, a `Blob`, so that an upload takes a file and a download is one.        |
| `lenient-nullable`     | 3.0.3+: `nullable` takes effect only through a sibling `type` that `enum`, `allOf`, `anyOf`, `oneOf`, or `$ref` do not override. 3.1+: no `nullable`.                                                                                                                                                                                                                                                            | `null` is admitted wherever `nullable: true` appears: `{ nullable: true, allOf: [Pet] }` is `Pet \| null`. |
| `lenient-request-body` | 3.0: a request body on `GET`, `HEAD`, or `DELETE` is to be ignored.                                                                                                                                                                                                                                                                                                                                              | The body is kept (Kubernetes delete options, Stripe), as 3.1+ allows.                                      |
| `lenient-ref-siblings` | 3.0: keywords next to `$ref` are ignored.                                                                                                                                                                                                                                                                                                                                                                        | They apply, as in 3.1+: the target intersected with them.                                                  |
| `lenient-keyword`      | A keyword or field from a later version: `const`, `prefixItems`, `patternProperties`, `if`/`then`/`else`, `additionalItems`, an array or boolean `items`, `type: "null"`, `type` arrays, boolean schemas, or a binary `contentMediaType` in 3.0; `webhooks` in 3.0; `query`, `additionalOperations`, `in: querystring`, or `itemSchema` before 3.2. The `schema` of a JSON sequence before `itemSchema` existed. | Applied; a JSON sequence's `schema` types each item.                                                       |
| `lenient-read-only`    | 3.1+: `readOnly` and `writeOnly` are annotations.                                                                                                                                                                                                                                                                                                                                                                | Required ones are required on one side only: [Input variants](#input-variants), as in 3.0.                 |
| `lenient-security`     | Without a security requirement, an operation needs no credentials.                                                                                                                                                                                                                                                                                                                                               | The client sends the credentials it is given, since the document declares schemes for them.                |

## Approximations

TypeScript cannot express everything JSON Schema can. Where it cannot, the generated type is wider than the schema, never narrower, except in these deliberate cases (and the ones above):

- **Shape keywords imply a shape.** A schema without `type` whose keywords constrain only objects (`properties`, `required`, `additionalProperties`, `patternProperties`) is typed as an object, and `items`/`prefixItems` as an array. In JSON Schema such a schema also accepts other values. In an `allOf` with a definite other type (`type: string`), the implied shape gives way, as it does to the alternatives of a referenced union. Below the first such union, where alternatives would multiply level by level, the type widens to either side instead (`{ b: unknown } | S`).
- **Unmentioned properties are assumed absent.** Without `additionalProperties`, objects get no index signature, so TypeScript's excess-property and weak-type checks reject extra properties in object literals. With only `patternProperties`, every extra property is typed by the pattern schemas.
- **`$dynamicRef` is resolved statically**, as if it were `$ref`.
- **Raw bytes are a `Blob` wherever a schema declares them.** A raw-bytes property inside JSON, a form field, or a parameter is typed `Blob`, although these carry text; the client refuses a Blob there. Such documents describe files, so this stays the type uploads and downloads need.
- **One-sided requiredness does not reach into references.** A property that a referenced `allOf` member requires stays required in requests even when another member declares it `readOnly` (and likewise for `writeOnly` in responses); the referenced schema's own type is not changed for one user of it.

Two narrowings come from outside JSON Schema itself:

- Discriminator values (see [Discriminators](#discriminators)) narrow alternatives by OpenAPI's discriminator contract, under which a value no mapping selects is invalid. Validation by the schemas alone would allow it.
- TypeScript compares properties named like `Object.prototype` members (`toString`, `constructor`) with those members, so an object literal that omits such an optional property may not type-check.

Validation that TypeScript cannot express is dropped, and the type is wider:

- Numeric and string constraints, `uniqueItems`, `contains`, `dependentRequired`, `dependentSchemas`, `unevaluated*`, `propertyNames`.
- `not` (except `not: {}`).
- `oneOf` exclusivity.
- The regular expressions of `patternProperties` keys.
- `additionalProperties: false` closing an object.
- An `allOf` whose unions, including those behind references and inside intersections, would multiply into more than 10,000 alternatives widens its largest ones until they would not: a union of objects to any object, other unions to `unknown`.

`integer` is `number`. The generator's soundness is tested against the official [JSON Schema Test Suite](https://github.com/json-schema-org/JSON-Schema-Test-Suite): every valid instance must type-check, apart from the cases above.
