# Test coverage map

The suite separates generated bytes, compiler contracts and runtime behavior. Run
`pnpm verify` for all three, plus lint and formatting. Commands and fixture conventions
live in [Conventions](../.agents/01-conventions.md).

| Evidence                       | Home                                                                                                       | What it establishes                                                                                                       |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Generated output               | `fixtures.spec.ts`, `__snapshots__/`                                                                       | Stable public modules for the client fixture and official OpenAPI examples; the generated bodies also compile             |
| Schema semantics               | `schemas.spec.ts`, `schema-composition.spec.ts`, `schema-projection.spec.ts`, `discriminator.spec.ts`      | TypeScript value sets, composition, recursion, input/output direction and transport projections                           |
| Retrieval and references       | `document-loading.spec.ts`, `references.spec.ts`                                                           | URI ownership, semantic discovery, local/remote boundaries, redirects, bounded work and cancellation                      |
| Operations and encodings       | `operations.spec.ts`, `content.spec.ts`, `form.spec.ts`, `multipart.spec.ts`                               | Generated operation descriptions and serialization plans, including their integration with the Node client                |
| Generation API and diagnostics | `generate.spec.ts`, `diagnostics.spec.ts`                                                                  | Accepted inputs, deterministic output, failure locations, precision limits and interruption                               |
| Static client contracts        | `types/client.ts`, `types/stream.ts`                                                                       | Call inputs, status narrowing, generic forwarding, media selection and inferred stream items                              |
| Generated consumer compilation | `client-types.spec.ts`, `contract.spec.ts`                                                                 | Fresh output consumed across modules, DOM/Node platform types, stricter compiler options and a heterogeneous API at scale |
| Browser requests and responses | `client-request.browser.ts`, `client-response.browser.ts`, `multipart.browser.ts`, `middleware.browser.ts` | Native Request/Response bodies, serialization, decoding and middleware ownership with a controlled transport              |
| Browser streaming              | `stream*.browser.ts`, `sse.browser.ts`, `jsonl.browser.ts`, `json-seq.browser.ts`                          | Byte framing, per-message byte limits, pull demand, backpressure, cancellation, cleanup and retry semantics               |
| Native network behavior        | `client-http.browser.ts`, `stream-http.spec.ts`, `client-node.spec.ts`                                     | Browser CORS, opaque responses, redirects and live HTTP teardown; Node Fetch streaming and Node-specific inputs           |
| CLI and documentation          | `cli.spec.ts`, `docs.spec.ts`                                                                              | File replacement/recovery, byte checking, diagnostics, executable examples and published resources                        |
| Compiler harness               | `typecheck.spec.ts`                                                                                        | Real cross-file compilation, rejected assignments, unused error directives and generated suppression handling             |

`*.spec.ts` runs in Node; `*.browser.ts` runs in the browser instances configured in
[vitest.config.ts](../vitest.config.ts), currently Chromium. Files under `types/` are
compiler inputs only: `pnpm typecheck` checks them; Vitest never executes them.
Tests that generate a consumer dynamically invoke the real compiler through
`helpers/tsc.ts`. It removes generated `@ts-nocheck` headers unless a test explicitly
checks the consumer-facing suppression itself.

The JSON Schema corpus in `json-schema-suite.spec.ts` checks valid instances for
assignability and invalid instances for constraints TypeScript can represent.
Its named approximation allowances are an upper bound on accepted failures, so
improved precision can pass without preserving a known limitation. This is a
type projection test, not a JSON Schema runtime validator.

`helpers/http.ts` owns each Node HTTP fixture's listen/close lifecycle, including
open connections after a failed assertion. `helpers/browser.ts` owns the shared
cross-origin browser fixture. Each request that needs mutable server state uses a
unique identifier.
