# Generate a module

Use the CLI for files and CI checks. Use `generate()` when your application needs the output as a string or needs custom document loading. Both produce the same [module](./generated.md) and resolve referenced documents automatically.

Generation requires Node.js 22 or later. Inputs can be JSON or YAML, addressed by a local path, a `file:` URL, or an HTTP(S) URL. The JavaScript API also accepts parsed objects. See [OpenAPI support](./openapi.md) for versions, reference boundaries, and type limitations.

## CLI

After installing `openapi-shape`, generate an ES module:

```sh
pnpm exec openapi-shape ./openapi.yaml -o src/api.ts
```

| Argument or option          | Meaning                                                                                                                                |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `<source>`                  | Required file path or URL.                                                                                                             |
| `-o, --output <file>`       | Write a `.ts` or `.mts` file, creating parent directories. Omit to print code to stdout. `.cts` and declaration files are unsupported. |
| `--check`                   | Compare generated bytes with `--output` without writing. Requires `--output`.                                                          |
| `--max-document-size <MiB>` | Positive whole-number limit per loaded document; default `10`. One MiB is 1,048,576 bytes.                                             |
| `-h, --help`                | Show usage.                                                                                                                            |
| `-v, --version`             | Show the package version.                                                                                                              |

Code goes to the output file or stdout; diagnostics and write/check status go to stderr. Warnings do not fail generation. Exit `0` means success or matching output; exit `1` means an argument, generation, or filesystem failure, or missing/outdated output in check mode.

### Keep generated code current

Commit the generated module and add paired scripts:

```json
{
  "scripts": {
    "api:generate": "openapi-shape ./openapi.yaml -o src/api.ts",
    "api:check": "openapi-shape ./openapi.yaml -o src/api.ts --check"
  }
}
```

Run `pnpm api:generate` after changing the description or upgrading the package; run `pnpm api:check` in CI. Check mode compares complete UTF-8 bytes, including formatting. A missing or stale output exits `1`; regenerate with the same installed package rather than editing the output. See [contract compatibility](./generated.md#contract-compatibility).

Writing uses a temporary file beside the resolved destination and renames it over the complete output. It follows existing symlinks and preserves ordinary permission bits; the destination directory must be writable. Hard links keep the old file, and ownership, ACLs, and special permission bits are not copied. This avoids partial replacement, not power-loss corruption; abrupt termination can leave a temporary file.

## Programmatic API

`generate(input, options?)` resolves to `{ code, diagnostics }`. The caller owns writing the string and presenting warnings:

```ts
import { writeFile } from "node:fs/promises"
import { generate, GenerateError } from "openapi-shape"

try {
  const { code, diagnostics } = await generate("./openapi.yaml")
  for (const d of diagnostics) console.warn(`${d.location}: ${d.code}: ${d.message}`)
  await writeFile("./api.ts", code)
} catch (error) {
  if (error instanceof GenerateError) console.error(error.diagnostics)
  throw error
}
```

Generation failures reject with `GenerateError`, whose `diagnostics` includes errors and any warnings found. Invalid numeric options reject with `TypeError`; cancellation rejects with `signal.reason`. A failed or canceled run returns no partial module. Unlike the CLI, `writeFile` above is a direct write without atomic replacement.

| Option                    | Default         | Meaning                                                                                    |
| ------------------------- | --------------- | ------------------------------------------------------------------------------------------ |
| `signal`                  | None            | Cancel loading and generation.                                                             |
| `loader(uri, { signal })` | Built-in loader | Return a successful `Response`, or `undefined` to delegate, directly or through a promise. |
| `maxConcurrentLoads`      | `8`             | Maximum active document loads, including hooks and body reading.                           |
| `maxDocumentBytes`        | `10485760`      | Streamed byte limit per document: 10 MiB.                                                  |

### Load an in-memory document with external references

Parsed object inputs can reference only resources inside themselves, even when a loader is supplied. To resolve external references, supply an entry URI and return the in-memory document from its loader:

```ts
import { generate } from "openapi-shape"

const document = {
  openapi: "3.1.2",
  info: { title: "Example", version: "1" },
  components: { schemas: { Pet: { $ref: "./pet.json" } } },
}
const entry = "https://spec.example.com/openapi.json"
const { code } = await generate(entry, {
  loader(uri) {
    if (uri === entry) return Response.json(document)
    return undefined
  },
})
console.log(code)
```

The entry URI locates the document and resolves `./pet.json` against the same origin. Returning `undefined` delegates external documents to the built-in loader. The entry also passes through parsing and document size limits.

When migrating, rename the `load` option to `loader`. The `base` option has been removed: replace `generate(document, { base: uri, … })` with `generate(uri, { loader, … })`, returning the document for that entry URI as above.

### Authenticate document loading

A loader receives an absolute `file:`, `http:`, or `https:` URI without a fragment. Delegate sources you do not handle, and pass its signal to your own asynchronous work. This example supplies a placeholder credential only to one origin:

```ts
import { generate, type DocumentLoader } from "openapi-shape"

const token = "replace-with-access-token"
const loader: DocumentLoader = (uri, { signal }) => {
  if (new URL(uri).origin !== "https://spec.example.com") return undefined
  return fetch(uri, {
    signal,
    redirect: "error",
    headers: { authorization: `Bearer ${token}` },
  })
}
const { code } = await generate("https://spec.example.com/openapi.yaml", {
  loader,
  signal: AbortSignal.timeout(15_000),
  maxConcurrentLoads: 4,
})
console.log(code)
```

Only `undefined` delegates; `null` is invalid. The response body must be a compatible Web stream or `null`. A nonempty `Response.url` sets the base for relative references; otherwise the requested URI does. Custom loaders still obey the [reference boundaries](./openapi.md#references).

### Limits and cancellation

Numeric limits must be positive safe integers. Size limits apply separately to the entry and each referenced document, including decompressed HTTP bytes. They do not limit total memory, parsed input objects, or bytes a custom loader buffers before returning.

Each load has a 30-second deadline covering its hook and body reading. The supplied signal combines that deadline with the caller's signal. Cancellation stops queued loads, cancels active bodies, and rejects even if a hook ignores its signal. Such a hook can continue outside the concurrency count; late responses are canceled. Generation checks cancellation between work units; parsing or one large schema can delay it.

The response media type selects JSON or YAML parsing. If unknown, the final URL's extension is used; otherwise parsing tries JSON, then YAML. YAML merge keys are supported; cyclic object graphs, including recursive aliases, are rejected. Recursive schemas expressed with `$ref` are supported.

## Diagnostics

Each diagnostic has `severity` (`error` or `warning`), a stable `code`, a human-readable `message`, and a `location`. Locations are JSON Pointers such as `#/components/schemas/Pet`, prefixed with the document URI for external sources. The CLI prefixes entry locations with the source path too.

Errors prevent output. Warnings identify invalid input, unsupported fields, or reduced type precision. Successful generation is not full OpenAPI/JSON Schema validation, and not every omitted constraint produces a warning.

| Code                      | Severity | Meaning                                                                                     |
| ------------------------- | -------- | ------------------------------------------------------------------------------------------- |
| `invalid-document`        | error    | Invalid root, cyclic objects, excessive nesting, or a pattern match timeout.                |
| `unsupported-version`     | error    | Missing or unsupported entry `openapi` version.                                             |
| `read-failed`             | error    | Entry document cannot be loaded or parsed.                                                  |
| `unresolved-ref`          | error    | Reference is missing, unreadable, unsupported, or forbidden.                                |
| `circular-ref`            | error    | Non-schema reference cycle.                                                                 |
| `ignored-field`           | warning  | A field cannot be applied, such as an operation server or unsupported encoding.             |
| `invalid-schema`          | warning  | Invalid schema type, value, literal, or empty composition.                                  |
| `circular-schema`         | warning  | A cycle through only references/compositions is cut.                                        |
| `schema-precision-loss`   | warning  | A type is widened at a [complexity boundary](./openapi.md#precision-and-complexity-limits). |
| `discriminator-mismatch`  | warning  | A discriminator conflicts with a schema or cannot narrow a branch.                          |
| `invalid-parameter`       | warning  | Malformed or duplicated parameter.                                                          |
| `path-parameter-mismatch` | warning  | Parameters and path template disagree.                                                      |
| `invalid-status-code`     | warning  | Invalid response status key.                                                                |
| `path-item-conflict`      | warning  | A nearer Path Item field overrides an inherited field.                                      |
| `renamed-schema`          | warning  | A generated declaration name was changed to avoid a collision.                              |
