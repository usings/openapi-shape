# Use the generated module

Generation produces one TypeScript ES module with no imports or runtime dependencies. Use its types directly or pass `contract` to the [client](./client.md). Keep the module generated: it combines compile-time API descriptions with the runtime metadata needed to send them correctly.

## Exports

| Export      | Purpose                                                                                  |
| ----------- | ---------------------------------------------------------------------------------------- |
| `Endpoints` | Declared operations keyed by `"METHOD /path"`.                                           |
| `Schemas`   | Named schema declarations, describing JSON values.                                       |
| `Webhooks`  | Incoming operations keyed by method and webhook name.                                    |
| `Callbacks` | Incoming callback operations, keyed by their parent operation, name, and URL expression. |
| `contract`  | Format version, endpoint registry, and a type-only association with `Endpoints`.         |

Endpoints contain declared `params`, `query`, `headers`, `cookies`, media-keyed `body`, and status-keyed `responses`. Response entries contain declared `headers` and media-keyed `content`. Undeclared request fields are omitted; an empty response is `{}`. Requiredness follows the operation: for example, a required request body produces `body` rather than `body?`.

<!-- example: standalone -->

```ts
import type { EndpointArgs } from "openapi-shape/client"
import type { Endpoints, Schemas } from "./api"

export type Pet = Schemas.Pet
export type CreatePetBody = Endpoints["POST /pets"]["body"]["application/json"]
export type PetPayload =
  Endpoints["GET /pets/{petId}"]["responses"][200]["content"]["application/json"]
export type CreatePetInput = EndpointArgs<Endpoints, "POST /pets">[0]
```

These descriptive types are not identical to client arguments: the client adds request options and ready bodies, makes ordinary declared headers optional, and excludes bodies on `GET`/`HEAD`. It excludes `CONNECT`, `TRACE`, and `TRACK` entirely. Use [client helpers](./types.md#forward-typed-calls) for actual call inputs and decoded results. Exact statuses, ranges, and `default` remain declared in `Endpoints`; the client applies [status precedence](./client.md#status-typing).

## Schemas and directional types

Every `components.schemas` entry becomes a declaration. Plain objects become interfaces; other values become type aliases. Valid names are preserved; unsupported characters become `_`, reserved words gain `_`, and collisions gain numeric suffixes with a `renamed-schema` warning. Referenced external schemas may also receive declarations, especially when reused or recursive.

Named schemas represent JSON: `date-time` remains `string`, `int64` remains `number`, and binary string annotations remain strings. TypeScript cannot prevent JavaScript integer precision loss beyond 2^53. Formats and constraints are preserved as JSDoc where applicable. Raw binary media and multipart file inputs use transport-specific `Blob` projections; see [media projections](./openapi.md#media-projections).

A required `readOnly` property becomes optional in requests; a required `writeOnly` property becomes optional in responses. Properties stay present in both views, and the client does not remove them from values. When both views are used, `Schemas.Name` describes responses and `Schemas.NameInput` describes requests. Multipart/file-part uses may create `NameMultipart` or `NameBinary` variants.

Annotations propagate through references and compositions without changing shared declarations or unrelated nested properties. In unions they affect their own branch. Large compositions may widen requirements with a [precision warning](./openapi.md#precision-and-complexity-limits).

## Incoming webhooks and callbacks

These describe exchanges your handler receives, not client calls. They have the operation shape above and are absent from `contract.endpoints`. Incoming requests use response-side schema views; responses you send use input views.

<!-- example: standalone -->

```ts
import type { Webhooks } from "./api"

type PetCreated = Webhooks["POST pet.created"]
export type PetPayload = PetCreated["body"]["application/json"]
export type Receipt = PetCreated["responses"]["200"]["content"]["application/json"]
```

Callback keys include the full chain, for example `"POST /subscribe > onEvent > POST {$request.body#/url}"`; nested callbacks extend it.

## Runtime metadata

The following is an excerpt from the module generated for the [example description](../docs/examples/petstore.yaml). `types` is optional for inference and is not populated at runtime:

<!-- example: generated -->

```ts
// Generated by openapi-shape. Do not edit.
// …
export const contract: {
  readonly version: 7
  readonly types?: Endpoints
  readonly endpoints: typeof endpoints
} = { version: 7, endpoints }
```

Every declared operation has an own registry entry, including methods unavailable to Fetch. It groups declared parameters under `parameters.path/query/header/cookie`, recording requiredness and optional `encoding`. Whole-query input uses `querystring.required` and `querystring.content`. It also records request body declarations with per-media encodings, and response declarations by status and media type. The client uses these declarations to match request and response media. The registry contains no executable schemas, server selection, or transport implementation.

The header records API metadata and declared root servers as comments; directive-like metadata is escaped. Formatting suppressions preserve the registry's one-entry-per-line layout. Lint and TypeScript diagnostic suppressions apply inside the generated file; exported types still check consuming code. Generator tests remove `@ts-nocheck` before compilation to check the generated declarations themselves.

## Contract compatibility

Generate with the package installed alongside the client. The client checks the contract format version and endpoints object; a mismatch requires regeneration. Editing the version number does not migrate a contract, and individual registry entries are not revalidated at client creation.

Keep the types and runtime registry together. After package upgrades, [regenerate and check](./generation.md#keep-generated-code-current) the whole module so call typing and serialization continue to describe the same API.

## Regenerate for contract version 7

Regenerate the entire module when migrating from earlier formats. The operation description is exported as `Endpoints`, and the registry is `contract.endpoints`. Runtime parameter declarations are grouped by location and include requiredness; whole-query input has its own content declaration. Request and response media remain explicit declarations, while JSON defaults belong to the client. Fetch-forbidden methods remain descriptive operations and are filtered by client types.

Calls select media through headers. Structured JSON calls may omit Content-Type when the client fallback or a literal client default establishes it. SSE reconnection requires an explicit retry option. `result()` rejects undeclared response statuses; `fetch()` retains native response ownership and conservatively types undeclared responses.
